● Sync for plain-file folders

Your folder, on every computer and online.

Obsidian Sync for any application.

File-first, agent-friendly. Pick any folder of plain files and folder-sync keeps it the same on your laptop, your desktop and the web, with version history. Any editor, script or local AI agent can just open the files.

How it works

A plain folder on your disk, a copy that's always online, sync in between.

01 · LOCAL FOLDER

Your files stay files

~/notes/plan.md · bom.json · sketch.png

Edit them with anything. Nothing has to go through an app.

⇄
02 · SYNC

Only what changed moves

rclone enginemanifest diff · push on change

A watcher sees each save, uploads the changed files and tells your other machines at once.

⇄
03 · ONLINE

Always-on copy, readable on the web

Cloudflare R2your bucket, or a hosted account

Your other computers pull it down; apps and the browser read the same files.

Philosophy

The folder is the database.

The folder on your disk is the truth; the web is a view of it. Nothing has to go through an app.

A

File-first

An AI agent on your machine reads and writes plain files with the tools it already has. No API, no SDK, no export step. If folder-sync disappeared, you would still have every file.

B

Obsidian Sync ergonomics

Make a folder and it is the same everywhere, fast, with history, without thinking about it. And you can see it online too, which is the one thing Obsidian Sync does not give you.

C

Off-the-shelf parts

rclone moves the bytes, Better Auth does sign-in, R2 or any S3-style store holds the copy, Cloudflare Workers run the small server. The code here is the glue those parts do not already provide.

D

One thing, done well

It does not understand what is inside your files; apps like Vibe Tracks do that. An overwrite or delete keeps the old copy for 30 days, and an empty or unmounted folder cannot wipe the online one.

E

Drop-in

An app keeps its data in a folder and gets sync, accounts and a sync view in 20 lines of code or fewer, with no server of its own. One sign-in works across every app that uses it.

F

Honest numbers

Every number on this page is generated from measurements. A gate never passes without its proof, and a target we miss is shown as missed.

Parts: core (Go CLI and engine, works alone) · server-cloudflare · ui · desktop Storage: R2, S3-compatible, Google Cloud Storage or a plain folder (docs/STORAGE.md) For apps: drop it into an app
Features

What works now, and what's coming.

Works now
  • Sync any folder across your computersLinux and macOS; each machine's files land on the others under hosts/<machine>/
  • Push, not pollinga save goes up at once; signed-in machines and pages hear about it in a fraction of a second
  • An online copy you can read on the webprivate by default; publish --public when you choose
  • Sign in from the browsera new machine shows a code you approve; it holds short-lived keys for your own files only, and you can revoke it
  • Runs in the backgroundsync --install-service writes the systemd, launchd or Task Scheduler entry
  • Ignore rulesgitignore syntax
  • A desktop appTauri installers for Linux, macOS and Windows; the macOS and Windows results are not yet in (gate G4)
  • One tree for everyonefolder-sync share: every machine, agent and web page edits the same files; two edits to different lines of a note merge, a collision becomes a conflicted copy
  • Swappable storageR2, AWS S3 and S3-compatible stores (Backblaze B2, Wasabi, MinIO), Google Cloud Storage, or a plain folder: one line in .folder-sync.toml
  • An account pageplans and a storage quota (Stripe in test mode), or bring your own bucket
  • Version historyold copies of replaced and deleted files, kept up to 30 days and thinned as they age; see what changed, download one, restore it
  • Activity logwhich machine changed what, and when, with each sync's time from disk to online and back
  • Deleted filesevery deleted file with a kept copy; restore one or many at once
  • The sync viewone <folder-sync-status> element any app drops in: the folder's state, its activity, versions and deleted files
  • folder-sync servethe same view on your own machine, on 127.0.0.1 behind a token; status and activity work offline
Coming
  • macOS and Windows proved in CIthe CI matrix builds and tests on both; G4 and G11 stay "not built yet" until their results are in
  • Production on targetthe objectives above show where the hosted service stands against each target today
Quick start

Download one file, sign in, point it at a folder.

1 · Download the CLI

One static binary, v0.2.0 (a pre-release). It fetches its pinned rclone on first init and checks its SHA-256.

$ mkdir -p ~/.folder-sync/bin; curl -fsSL https://github.com/zacharyyamaoka/folder-sync/releases/download/v0.2.0/folder-sync-linux-amd64 -o ~/.folder-sync/bin/folder-sync; chmod +x ~/.folder-sync/bin/folder-sync

Then put ~/.folder-sync/bin on your PATH. Check it: SHA256SUMS. The macOS builds are not signed.

Or build from source

$ git clone https://github.com/zacharyyamaoka/folder-sync
$ go -C folder-sync build -o ~/.folder-sync/bin/folder-sync ./cmd/folder-sync

2 · Bring your own bucket

folder-sync stores the online copy in a Cloudflare R2 bucket. Use your own: it's on your Cloudflare account, so you pay R2's prices (it has a free tier) and nobody else can see it.

  1. Cloudflare dashboard → R2 → Create bucket, say folder-sync. Leave public access off.
  2. R2 → Manage API tokens → Create API token: Object Read & Write, for that bucket only. Copy the account id, the access key id and the secret.
  3. Store the key on each machine (asked for once, kept in ~/.folder-sync/credentials.json, mode 0600):
$ folder-sync login --key
# then, in the folder you want synced:
$ folder-sync init --project notes --bucket folder-sync
$ folder-sync sync --watch
# the same two lines on your other computer, in its own folder

With your own bucket a save uploads at once and your other computers pull every 10 s (push between machines needs an account). folder-sync publish --viewer writes a read-only web viewer (R2-Explorer, behind Cloudflare Access) for you to deploy. Cloud agents can set FOLDER_SYNC_ACCOUNT_ID, FOLDER_SYNC_ACCESS_KEY_ID and FOLDER_SYNC_SECRET_ACCESS_KEY instead of login --key.

Hosted accounts (Google sign-in, push between machines, the web view) are invite-only. Have one? Sign in here, and run folder-sync login on each computer: it prints a code you approve in the browser. Then open the live demo: your folders online, each computer's files, and recent activity with each sync's time.
