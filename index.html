folder-sync

A folder on your computer, kept in sync online and across your machines.

Early (v0). Open source on GitHub.

Install

From source, with Go 1.27.3 or newer. There are no prebuilt binaries yet.

git clone https://github.com/zacharyyamaoka/folder-sync
go -C folder-sync build -o ~/.folder-sync/bin/folder-sync ./cmd/folder-sync

Put ~/.folder-sync/bin on your PATH. The first init downloads rclone, checks it against a pinned checksum, and keeps everything under ~/.folder-sync/.

Use

folder-sync login
cd ~/notes
folder-sync init
folder-sync sync --watch
folder-sync status
  • login signs this machine in: it prints a code, you approve it in a browser. login --key stores a Cloudflare R2 bucket key instead.
  • init makes the current folder a synced folder.
  • sync --watch pushes this machine's changes and pulls your other machines' until you stop it. sync --install-service writes the autostart file for your system and prints the command that enables it.
  • status shows the last push and pull and which machines it has seen.

To make a folder readable on the web: folder-sync publish --public. --private undoes it.

How it works

  • Your files stay plain files in a plain folder. Any editor or tool works on them.
  • rclone moves them to a Cloudflare R2 bucket, the always-on copy.
  • Each machine pushes its own files. Your other machines' files arrive read-only under hosts/<machine>/ in the folder.
  • A file you delete or overwrite is first moved to _trash/ in the bucket.

What it is not

  • Not a collaborative editor. Two machines do not edit one file together, and nothing is merged. Two-way shared folders are not built yet.
  • Not a backup app. A delete on one machine is a delete in the synced copy. _trash/ is a safety net, not a backup plan.
  • Not aware of what is in your files. It moves them and does nothing else with them.

Platforms

Linux and macOS. Windows is next: it builds, but has not been run on Windows yet.
